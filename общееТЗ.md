1. Цель проекта
Разработка цифровой платформы (Web + Mobile), позволяющей пользователям:
•	находить туры 
•	фильтровать и просматривать детали 
•	бронировать и оплачивать поездки 
MVP-фокус:
•	каталог туров 
•	фильтрация 
•	бронирование 
•	базовая авторизация 
❗ AI-функции не входят в критический MVP и реализуются после основной логики.
________________________________________ 
2. Архитектура системы
Система реализуется по клиент-серверной модели:
•	Frontend: React Native 
•	Backend: Django + Django REST Framework 
•	База данных: PostgreSQL 
•	Аутентификация: JWT 
•	Интеграции: платежные системы, карты

4. БИЗНЕС-ЛОГИКА (КРИТИЧНО)
4.1 Сценарий бронирования
1.	Пользователь нажимает “Забронировать” 
2.	Отправляется запрос: 
POST /api/bookings
3.	Backend: 
•	проверяет доступность мест 
•	создаёт Booking со статусом pending 
4.	Возвращает: 
•	booking_id 
•	статус 
5.	Пользователь переходит к оплате 
________________________________________
4.2 Оплата
POST /api/payments
Backend:
•	создаёт Payment 
•	связывает с booking 
После успешной оплаты:
•	booking → confirmed 
•	payment → success 
Если не оплачено:
•	booking остаётся pending (с возможностью отмены) 
________________________________________
4.3 Ограничения
•	Нельзя забронировать больше, чем max_people 
•	Бронь без оплаты аннулируется (логика таймера реализуется позже) 
•	Один пользователь может иметь несколько броней
